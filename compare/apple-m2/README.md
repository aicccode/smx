# Apple M2：改造前、高安全版、高性能版与 OpenSSL、BouncyCastle 的性能对比

[中文](README.md) | 测试数据的英文和西班牙语汇总见仓库根目录的 [README.en-US.md](../../README.en-US.md)、[README.es-ES.md](../../README.es-ES.md)

本目录记录 2026-11-06 在一台空闲 Mac 上做的对比。每种语言测三个版本：

- **改造前：** 提交 `3397c6d`。
- **`security`（高安全版）：** SM4 为常数时间实现，结果文件名中记为 `new`，目录 `results-2026-11-06/`。
- **`main`（高性能版）：** SM4 为查表实现，结果文件名中记为 `perf`，目录 `results-2026-11-06-main/`。

同时测了 OpenSSL 3.0.13、OpenSSL 3.6.5 和 BouncyCastle 1.86。两个分支除 SM4 外代码完全相同，实测 SM2、SM3 各项相差的中位数为 0.1%。x86 上的对比见 [上一级目录](../README.md)。

## 测试环境与方法

- **机器：** Apple M2（4 个性能核 + 4 个能效核），8 GB 内存，macOS 14.1.1，接交流电，测试期间没有其他负载。所有程序依次运行，不并行；整个过程在 `caffeinate` 下进行，每个程序启动前等待 10 秒冷却。`state.log` 记录了每次启动前的负载和温控状态。
- **计时：** 每项操作先预热，再采 7 个样本，每个样本至少 200 ms，取中位数。每种实现完整运行 3 轮，表中是 3 轮中位数的中位数。各实现 3 轮之间差异的中位数在 0% 到 3.7% 之间。
- **同一套测试程序测所有版本：** 每种语言只有一份测试程序，分别链接各版本的代码，只调用各版本都有的接口。计时前先做正确性检查，例如签名能通过验签、改动消息后验签失败、加解密能还原、密钥交换双方结果一致且确认值通过。任何一项不通过，程序就会退出。
- **操作：** SM3 对 64 B、1 KiB、1 MiB 输入求哈希；SM4 为 CBC + PKCS#7；SM2 签名使用默认用户 ID，加解密的明文为 32 字节；密钥交换包含双方的全部计算和确认值校验。
- **编译器与运行时：** Apple clang 15.0.0（`-O3`）、rustc 1.94.1（release）、Go 1.25.14、.NET 8.0.427、JBR 17.0.11（Java 和 BouncyCastle 共用）、Node.js 22.23.4、Python 3.9.6（系统自带）、Swift 5.10（`-O -wmo`）。
- **OpenSSL：** 从官方源码包编译，下载后核对过 SHA-256。配置为 `./Configure darwin64-arm64-cc no-shared no-tests`，测试程序静态链接 `libcrypto.a`，通过 `EVP` 接口调用。OpenSSL 不提供 SM2 密钥交换。
- **BouncyCastle：** `bcprov-jdk18on-1.86`，使用轻量级 API，不经过 JCA。密钥交换使用 `SM2KeyExchange`，并带确认值。

## 结论

**高性能版（`main`）**

- **所有语言、所有操作、所有数据长度都比改造前快**，没有任何一项倒退。
- **SM4 与 OpenSSL 3.6.5 相比：** 1 MiB 加密时，Rust（155 MB/s）、Swift（139）、C（136）、Go（126）快于 OpenSSL（122），Java（113）、C#（107）、JavaScript（100）接近它。1 MiB 解密时，Rust（839）、Go（396）、C（373）、C#（175）快于 OpenSSL（141），Java 与它持平。
- **SM4 与高安全版相比：** 加密快 2 到 7 倍（Python 约 25 倍），密钥扩展快 1.7 到 4.8 倍（Python 11 倍）。解密方面，Rust 和 Python 在长数据上与高安全版持平：前者本来就使用 ARM AES 指令，后者的比特切片批处理本来就比查表快，两者都予以保留。

**高安全版（`security`）**

- SM4 不做依赖秘密数据的查表。Go、C#、Java、Python 在 ARM 上没有可用的硬件指令，只能用布尔电路 S 盒，因此加密只有改造前的 26% 到 66%，C 为 83%；C#、Java 的解密也比改造前慢。C 和 Rust 在 ARM 上使用 AES 指令，解密分别达到 195 MB/s 和 839 MB/s。
- 其余各项与高性能版完全相同。

**SM2 与 SM3（两个分支相同）**

- **和改造前比：** 所有语言、所有操作都明显变快。签名提速 8 倍（Python）到 228 倍（JavaScript），密钥交换提速 2.1 到 128 倍，SM3 提速 1.3 到 4.3 倍。
- **和 OpenSSL 3.6.5 比：** OpenSSL 3.6.5 在 ARM 上比 3.0.13 快很多，签名从 162 µs 降到 55 µs。即便如此，Rust、Go、Swift 的签名仍快 1.4 到 1.7 倍，密钥生成快约 2 倍，加解密快 1.1 到 1.6 倍；Go、Swift 的验签快约 2 倍。C、C# 的签名略快于它，但 C# 的验签和加解密较慢，Java 和 JavaScript 各项都较慢。SM3 方面，Rust、C#、Swift 略快，JavaScript 持平，C、Go 慢 9% 到 12%。

**关于 OpenSSL 在 M2 上的 SM4：** 已在 OpenSSL 3.6.5 源码中核实（`include/crypto/sm4_platform.h` 和 `crypto/armcap.c`）：在 ARM 上，OpenSSL 只在三种情况下使用汇编实现——CPU 有 SM4 扩展指令，或者是 Neoverse N1/V1，或者是鲲鹏 920。M2 不属于其中任何一种，所以 OpenSSL 使用 `crypto/sm4/sm4.c` 中的通用 C 实现，同样是查 4 张 1 KiB 的表，与本库高性能版属于同一类做法。

**和 BouncyCastle 比：** Java 的 SM2 签名快 7.5 倍，加解密快约 9 倍，密钥交换快 13 倍；SM3 两者持平。SM4 方面，高性能版的加密是 BouncyCastle 的 1.6 倍，解密是 2 倍；高安全版只有它的约三分之一。BouncyCastle 的 SM4 也是查表实现。

**需要说明的几点**

- 多数语言的接口以十六进制字符串或文本收发数据，各版本都包含这部分转换，所以版本之间的对比是公平的。与直接处理字节的 OpenSSL、BouncyCastle 相比，这一点对本库略为不利。例如 Swift 的 SM4 解密（37.7 MB/s）主要花在十六进制解码和 UTF-8 校验上。
- Python 改造后默认启用按密钥缓存（可用 `SMX_DISABLE_KEY_CACHE=1` 关闭）。测试中签名和验签反复使用同一个密钥，因此会受益于缓存。Python 高性能版处理 32 KiB 以上的数据时，会按需建立约 5 MB 的 16 位宽表。
- Java 和 JavaScript 有几项倍数特别大，原因在于改造前的实现：Java 生成密钥时有一个多余的筛选循环；JavaScript 签名时会多出约 22% 的重试，大数运算也很慢。
- 每种语言测试中的具体调用方式和注意事项，见各自的 `kits/<语言>/NOTES.md`。

## 复现

需要的工具：Xcode 命令行工具、rustup，以及 Go、Node.js、.NET 8 SDK、JDK 17 和自行编译的 OpenSSL。这些工具都可以装在 `~/smx-bench/tools` 这样的独立目录中，不需要改动系统。

```bash
# 改造前与 security：base 为 3397c6d，new 为 security 分支
compare/apple-m2/prepare.sh 3397c6d security
compare/apple-m2/build-kits.sh c rust go csharp java javascript python swift
# OpenSSL：在 kits/openssl 中执行
#   cc -O2 -I$OSSL/include -o ob-<版本> openssl_bench.c $OSSL/lib/libcrypto.a
# BouncyCastle：把 bcprov-jdk18on-1.86.jar 放到 kits/bc 中，然后执行
#   javac -cp bcprov-jdk18on-1.86.jar -d cls BcMacBench.java
caffeinate -dimsu compare/apple-m2/run-all.sh          # 约 2 小时，结果写入 results/

# main：先删除 kits/*/base 和 kits/*/new，再把 new 换成 main，只测这一侧，结果记为 perf
compare/apple-m2/prepare.sh 3397c6d main
compare/apple-m2/build-kits.sh c rust go csharp java javascript python swift
RESULTS=results-main OPENSSL_VERSIONS= SKIP_BC=1 SIDES=new LABEL_new=perf \
  caffeinate -dimsu compare/apple-m2/run-all.sh        # 约 25 分钟

python3 compare/apple-m2/table.py results results-main                      # 完整表格
python3 compare/apple-m2/table.py --summary results results-main            # 顶层 README 中的汇总表
python3 compare/apple-m2/table.py --summary --lang en results results-main  # 英文；西班牙语用 --lang es
python3 compare/apple-m2/summarize.py results-main                          # 原始中位数和各轮差异
```

`run-all.sh` 可以通过 `ROUNDS`、`COOLDOWN`、`LANGS`、`SIDES`、`LABEL_new`、`OPENSSL_VERSIONS`、`SKIP_BC`、`TOOLS`、`RESULTS`、`JAVA_HOME` 调整。原始输出中，`*.txt` 每行为“操作、中位数 µs、最小值 µs”，`*.err` 包含版本信息和正确性检查的输出。
